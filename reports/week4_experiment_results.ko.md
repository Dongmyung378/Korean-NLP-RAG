# 4주차 결과 요약

[English](week4_experiment_results.md) | [한국어](week4_experiment_results.ko.md)

## 검증 범위

Kaggle에서 실행한 검색·답변 실험과 로컬 앱 평가를 정리했다. 인용 지표는 저장된 답변을 이용한 로컬 후처리 결과이며, 추론 결과와 구분해 기록했다.

KorQuAD 문맥 960개를 5,889개 청크로 나누고 고정 질문 1,000개로 검색을 평가했다. 답변 비교는 그중 고정된 100개 질문을 사용했다. 기존 개발에 사용한 표본이므로 새 held-out 성능은 아니다.

## 검색 결과

| 방법 | Recall@1 | Recall@5 | Recall@10 | Recall@20 | MRR@10 | nDCG@10 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| BM25 | 0.6090 | 0.7860 | 0.8240 | 0.8510 | 0.6870 | 0.6958 |
| Dense retrieval | 0.5490 | 0.7950 | 0.8510 | 0.9010 | 0.6535 | 0.6767 |
| Hybrid RRF | 0.6620 | 0.8590 | 0.9000 | 0.9350 | 0.7452 | 0.7604 |
| Hybrid RRF + reranker | 0.6880 | 0.9020 | 0.9220 | 0.9350 | 0.7795 | 0.7942 |

BM25는 첫 순위에서, dense retrieval은 넓은 후보 범위에서 강했다. RRF로 두 검색기를 결합한 뒤 reranker를 적용하자 상위 순위의 검색 성능이 개선됐다. Recall@20은 같은 후보 집합을 재정렬하므로 변하지 않았다.

## 노트북 답변 결과

| 방법 | 정답 포함률 | 근거 문자열 일치율 | 답변 단계 시간/질문 |
| --- | ---: | ---: | ---: |
| Qwen Direct Top-3 | 0.53 | 0.78 | 0.459초 |
| Qwen Question-Focused Top-3 | 0.53 | 0.78 | 0.448초 |
| Qwen Focused + Validation | 0.55 | 0.89 | 0.558초 |
| Extractive QA Reader | 0.74 | 1.00 | 0.031초 |
| Reader-First 최종 답변 | 0.74 | 1.00 | 0.031초 |

정답 포함은 정규화한 정답 문자열이 답변에 있는지 확인한 값이다. Reader 후보는 빈 답을 제외한 209개이며, 100문항 모두 Reader 답변이 선택됐다. 이 표본에서는 Qwen fallback이 사용되지 않았다.

이전 실행의 정답 포함률은 0.64였다. 리랭킹 결과와 실행 환경도 달라졌으므로, 0.74로의 상승을 빈 답 처리 변경만의 효과로 해석할 수는 없다.

시간은 Kaggle Tesla T4에서 기록한 답변 단계의 평균이다. 모델 로딩·검색·리랭킹 시간은 제외됐다. Qwen 생성 비용도 별도이므로 0.031초를 전체 앱의 응답 시간으로 표기하면 안 된다.

## 인용 지표의 계산 기준

Reader의 인용은 실제 답을 추출한 청크를 가리킨다. 원래 실행에서는 한 글자 답변을 제외하는 조건 때문에 ‘진’, ‘열’ 같은 답의 인용이 누락됐다. 후처리에서는 한 글자 답도 허용했으며 Qwen의 검증 조건은 변경하지 않았다.

저장된 답변·후보만 사용해 인용과 표·그림을 로컬에서 다시 계산했다. 답변 변경은 0개이며 GPU 추론은 하지 않았다. 근거 일치율과 인용률은 0.97에서 1.00으로 바뀌었다. ‘고,’ 같은 틀린 추출 결과도 원문에는 있으므로, 인용률 100%는 정답률 100%가 아니다.

후처리한 노트북 셀에는 `local_postprocessing` 메타데이터를 남겼다. [후처리 기록](week4_postprocessing.json)에 입력·출력 해시와 변경 범위를 저장했으며 기존 Kaggle 추론 시간은 보존했다.

## 남은 오류

| 분류 | 질문 수 |
| --- | ---: |
| 정답 문자열 포함 | 74 |
| 근거는 검색했지만 Reader 추출 실패 | 15 |
| Top-3 근거에서 정답을 찾지 못함 | 11 |

답이 있는 질문에서의 실험이므로, 이 결과만으로 답이 없는 질문의 거절 성능을 판단할 수 없다.

## 로컬 앱 평가

| 항목 | 결과 |
| --- | ---: |
| 정답 문자열 포함 | 67/100 |
| 답변 반환 | 79/100 |
| 답변 보류 | 21/100 |
| 반환한 답변 중 정답 문자열 포함 | 67/79 (84.8%) |
| 평균 질의 시간, 로딩 제외 | 0.084초 |
| 모델 로딩 시간 | 13.99초 |
| 수작업 무응답 점검에서 보류 | 5/6 |

로컬 앱은 후보별 RRF 0.025, reranker 0.50, Reader 0.10 기준과 명시적 연도 검사를 사용하고 Qwen fallback은 사용하지 않는다. 노트북의 74%와 로컬의 67%는 서로 다른 답변 정책의 결과다.

Python 3.12.7, PyTorch 2.5.1+cu121, Transformers 5.16.1, CUDA에서 실제 검색부터 답변까지 다시 실행했다. [지표·입력 해시](local_evaluation/metrics.json), [100개 답변](local_evaluation/predictions.json), [무응답 점검 결과](local_evaluation/unanswerable_probes.json)를 저장했다.

무응답 6문항 중 날씨, 개인정보, 미래 공연, 잘못된 연도, 문맥에 없는 식사 질문은 보류했다. 팬클럽 ‘해체식’이라는 잘못된 전제에는 날짜를 반환했다. 알려진 실패 사례를 포함한 소규모 점검이므로 일반적인 무응답 성능으로 해석하지 않는다.

## 재현 명령

- 코드 및 저장 결과 검증: `python -m unittest discover -s tests -v`
- 로컬 실제 추론 평가: `python -m korean_rag.evaluate --device auto --save-dir reports/local_evaluation_rerun`
- 모델 없이 인용·표 재계산: `python scripts/refresh_week4_reports.py`

보고서 재생성 명령은 결과 파일과 노트북의 후처리 출력을 갱신한다. 실행 조건과 원본 보관 안내는 [노트북 README](../transformer/notebooks/README.ko.md)에 있다.
