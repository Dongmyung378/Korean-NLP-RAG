# 공개 단위 검사 검증

[English](verification-tests.md) | [한국어](verification-tests.ko.md) | [수치 기록](verification-tests.json)

별도로 준비한 Windows와 Linux CPU 환경에서 공개 검사 전체가 통과했습니다. 각 전체 실행은 112개 중 109개 통과, 선택적인 과거 아티팩트 검사 3개 생략, 실패 0개입니다. 코드 검증이며 모델 정답률 벤치마크는 아닙니다.

| 환경 | Python | PyTorch | 통과 | 과거 자료 생략 | 실패 | 단위 검사 시간 |
| --- | --- | --- | ---: | ---: | ---: | ---: |
| 별도 Windows CPU 가상환경 | 3.12.7 | 2.14.0+cpu | 109 | 3 | 0 | 16.044초 |
| 격리된 Linux CPU 가상환경 | 3.12.15 | 2.14.0+cpu | 109 | 3 | 0 | 4.165초 |

두 환경 모두 전역 설치 패키지를 상속하지 않습니다. Linux 검사는 같은 컴퓨터의 기존 Docker 네이티브 볼륨과 임시 `python:3.12-slim` 컨테이너에서 Transformers 5.17.0과 CPU 스레드 4개로 실행했습니다. 네트워크를 차단하고 Hugging Face 오프라인 모드를 켰으며 CUDA는 사용할 수 없는 환경입니다. 현재 소스 디렉터리는 읽기 전용으로 연결했습니다. 실행 후 임시 컨테이너를 제거했고 준비된 환경 볼륨은 보존했습니다.

검사 파일 두 개가 임시 데이터를 소스 경로 아래에 만들던 부분을 운영체제의 쓰기 가능한 임시 경로로 바꿨습니다. 검증 조건은 그대로 유지해 읽기 전용 저장소에서도 검사할 수 있게 했습니다. 고정된 핵심 소스 19개는 기록된 해시와 비교했으며 변경이 없습니다. 기존 Windows 전체 검사 기록은 이 검사 전용 경로 수정 전의 결과이고 Linux 전체 검사는 수정된 파일을 검증한 결과입니다.

Linux 첫 실행은 5.267초에 통과했습니다. 상세 출력 로그를 보존한 두 번째 실행은 4.165초에 통과했습니다. JSON 기록에서 두 실행을 구분하고 개인 경로 대신 로그의 SHA-256을 제공합니다. 검사에는 무작위로 생성한 작은 모델에서 최적화를 한 번 수행하는 CPU 학습 검사가 포함됩니다. 공개 실행 모델의 다운로드나 전체 데이터셋 추론이 필요한 검사는 아닙니다.

생략된 3개는 공개 소스 폴더 밖에 보관한 과거 Week 4 결과 아티팩트 검사입니다. 생략을 통과로 계산하지 않습니다. 이 검증은 같은 컴퓨터에서 수행한 격리 환경 검증이며 [호스팅된 CI 상태](ci-status.ko.md)와 구분합니다. 계정의 Actions 비활성화로 GitHub가 HTTP 422를 반환해 워크플로를 시작하지 못했으므로 호스팅된 CI 통과를 주장하지 않습니다.

실행 환경을 준비한 뒤 공개 검사 명령은 다음과 같습니다.

```sh
python -m unittest discover -s tests -v
```
