# 답변 보류 평가 방법

[English](no_answer_methodology.md)

새 평가 세트는 고정된 지식베이스가 뒷받침하지 않는 대상과 관계에 대해 시스템이 답변을 보류하는지 확인합니다. 개발용 80문항과 최종 평가용 80문항을 구성했으며, 각 세트에 가상 단체의 소재지, 가상 단체의 인물, 조작된 관계, 가상의 미래 행사 질문을 각각 20개씩 포함했습니다.

각 질문에 등장하는 가상 대상은 평가를 위해 새로 만들었으며 별칭을 정의하지 않았습니다. 해당 대상에 관한 사실도 지식베이스에 추가하지 않았습니다. 질문은 반드시 그 대상의 속성이나 관계를 요구합니다. 이름이 기존 자료와 우연히 겹치지 않는지 확인하기 위해 지식베이스 전체의 원문과 제목을 정규화하여 검사합니다. 정답 없음의 근거는 이러한 통제된 구성과 질문이 요구하는 대상 관계입니다. 자연어 질문에서는 정답 문자열이 검색되지 않는다는 사실만으로 답할 수 없다고 판정하지 않습니다.

개발용 질문은 정답이 있는 개발 세트의 원문 문단 50개를 사용하고, 최종 질문은 최종 세트의 문단 80개를 사용합니다. 양쪽 세트는 기반 문단, 가상 대상의 전체 이름, 동일한 질문 템플릿을 공유하지 않습니다. 원문 기사나 넓은 문장 패턴은 겹칠 수 있습니다. 질문 구성에는 모델 실행이나 모델의 실패 사례를 사용하지 않았습니다. 최종 추론은 채택할 설정과 소스, 모델 파일, 두 평가 세트의 해시를 동결한 뒤에만 수행합니다.

기존에 수작업으로 선택한 질문 6개는 회귀 검증용으로 별도 보관합니다. 팬클럽 해체식 질문은 고정된 자료에서 뒷받침되지 않는 행사에 해당합니다. 팬클럽을 언급한 문단 8개를 검토하고 전체 자료를 검색하여, 원문에 있는 2014년 3월 29일 창단식과 질문이 요구하는 해체식을 구분했습니다. 검토 범위와 문단 ID, 해시를 기록했으며 현실의 모든 행사에 관한 사실을 단정하지 않습니다. 이 검토는 외부 사람의 독립 평가가 아니며, 기존 질문 6개를 새 합성 최종 평가의 분모에 포함하지 않습니다.

결과는 유형별 보류 횟수와 보류율, 잘못된 답변 반환 횟수와 비율로 제시합니다. 정답이 있는 질문의 답변률과 반환한 답변의 Exact Match도 함께 확인합니다. 보류 기준을 채택하려면 개발 세트의 오답 반환률이 최초 모델보다 높아지지 않고, 정답이 있는 질문의 답변률 감소가 2%p 이내이며, 사전에 정한 EM 또는 F1 개선 기준을 충족해야 합니다. 오답 반환률 10%는 지향점이며 답변률을 크게 낮추도록 허용하는 기준이 아닙니다. 모든 조건을 만족하는 후보가 없으면 기존 설정을 유지합니다.

채택 여부는 후보와 동일한 장치에서 측정한 최초 모델을 기준으로 판단합니다. CPU와 GPU의 미세한 연산 차이 때문에 답변 구간 점수와 CLS 보류 점수가 거의 같은 경우 판정이 바뀔 수 있습니다. 이를 완화하기 위해 Reader 후보 4개 모두에 고정된 `null_score_margin=1e-6`을 적용합니다. 설정 선택 전에 정한 수치 안정성 보정이며, 개발 성능에 맞춰 여러 값을 탐색하지 않습니다. 최초 모델의 대조 실험에는 기존의 여유값 0을 유지합니다. 이 보정은 거의 같은 점수를 보류하도록 하지만, 모든 하드웨어에서 동일한 비트 단위 결과나 모든 수치 오차의 제거를 보장하지 않습니다.

이 평가는 합성 질문을 이용한 고정 지식베이스 검증입니다. 가상 이름이나 명시적인 미래 연도는 자연스러운 모호한 질문보다 쉽게 거절할 수 있습니다. 따라서 실제 사용자 질문의 보류 성능, 사람의 독립 검토, 일반적인 환각 방지 능력을 입증했다고 설명하면 안 됩니다.

로컬 원문과 평가 명세를 이용해 재생성할 수 있습니다.

```powershell
python -m scripts.prepare_abstention --benchmark-dir PATH_TO_BENCHMARK --output-dir NEW_OUTPUT_DIRECTORY
```

기존 출력 폴더에는 덮어쓰지 않습니다. 결과 명세는 원문 지식베이스와 정답이 있는 평가 세트, 질문 구성 규칙과 생성한 파일을 SHA256으로 연결합니다.
