# 포트폴리오 공개본 측정 결과

[English](results.md) | [한국어](results.ko.md)

최종 개발 모델은 답이 있는 보류 평가 501문항 중 367문항에 정확히 답했습니다. 최초 개발 모델의 312문항보다 55문항 늘었습니다. 검색과 답변 품질은 개선됐지만 합성 무응답 질문에서 잘못 답한 경우와 처리 시간이 증가했습니다. 이 한계까지 결과에 포함했으며, 최종 결과를 보고 설정을 다시 선택하거나 조정하지 않았습니다.

## 결과 비교를 읽는 방법

대응 비교는 두 구현에 같은 질문을 입력해 질문별로 결과가 어떻게 달라졌는지 확인하는 방식입니다. 동결은 최종 추론 전에 사용할 설정과 파일 식별 정보를 기록했다는 뜻입니다. 개발 질문으로 설정을 고르고 최종 평가 질문으로 결과를 측정했으며, 과거 데이터 노출에 관한 한계는 아래에 공개합니다.

EM은 정규화 후 정답과 정확히 일치하는지를 보고, 문자 F1은 정답과 부분적으로 겹치는 정도를 평가합니다. Recall@5는 검색 단계의 지표로, 상위 후보 다섯 개 중 하나가 정답 구간 전체를 포함해야 성공입니다. gold는 평가 자료에 주어진 정답 주석을 뜻합니다. 답변 제공률은 정답 여부와 관계없이 응답한 비율이며, 합성 무응답의 보류 결과는 근거가 없는 별도의 통제 질문에서 측정합니다. 분모가 다른 항목을 하나의 정확도처럼 합쳐 해석하지 않습니다.

시간 지표에서 p50은 측정한 요청 시간의 중앙값이며, p95는 측정한 요청 중 약 95%가 그 시간 이내에 끝났다는 뜻입니다. 초기 모델 로딩 시간은 모델을 준비한 뒤 질문을 처리하는 시간과 구분합니다.

## 동결한 모델의 최종 대응 비교

| 측정 항목 | 최초 개발 모델 | 최종 개발 모델 | 변화 |
| --- | ---: | ---: | ---: |
| 정답 일치율 EM, 답이 있는 501문항 | 62.28% (312/501) | 73.25% (367/501) | +10.98%p |
| 한국어 문자 F1, 동일 501문항 | 70.55% | 79.94% | +9.39%p |
| 정답 구간 전체를 찾은 Recall@5, 동일 501문항 | 91.62% (459/501) | 96.61% (484/501) | +4.99%p |
| 답변 제공률, 동일 501문항 | 86.03% (431/501) | 87.82% (440/501) | +1.80%p |
| 별도 합성 무응답 80문항의 보류 | 79/80 (98.75%) | 76/80 (95.00%) | -3.75%p |
| 동일 합성 80문항의 잘못된 답변 | 1/80 | 4/80 | 3건 증가 |
| 전체 581문항 평균 GPU 처리 시간 | 105.34 ms | 209.53 ms | 1.99배 |

두 모델을 동일한 501문항과 별도 합성 무응답 80문항으로 평가했습니다. 측정 환경은 Windows 11, Python 3.12.7, PyTorch 2.14.0+cu130, NVIDIA RTX 3060 Laptop GPU입니다. GPU 처리 시간은 모델 적재를 제외하고 검색부터 설정된 Reader의 답 추출까지 포함합니다. 평균, 중앙값, p95는 최초 105.34/103.38/125.02 ms, 최종 209.53/206.98/247.23 ms였습니다. 모델 적재는 각각 15.55초와 19.10초였습니다. 개발 작업 중 같은 컴퓨터에서 얻은 측정값이며 모든 장치의 지연 시간이나 전용 서버 처리량을 의미하지 않습니다.

평가 자료는 공개 KorQuAD 검증 데이터에서 이번 프로젝트의 설정 선택에 사용하지 않도록 분리한 문항입니다. 공식 비공개 테스트와 다르고 공개 사전 학습 모델의 데이터 노출 가능성도 남아 있습니다. 문단과 정규화 질문 그룹은 분리했지만 개발과 최종 자료의 기사 19개는 겹칩니다. EM과 문자 F1은 공식 한국어 정규화 방식에 맞춰 계산했으며, Recall은 정답 문단에서 정답 구간 전체를 포함한 청크가 재정렬 결과에 있는지 측정합니다.

## 개선 내용과 중단한 실험

1. **평가 자료와 경계 정비.** 문단 단위로 개발 304문항과 최종 501문항을 분리했습니다. 기존 1,000문항 평가 노출과 확인 가능한 최초 학습 문단은 최종 평가 대상에서 제외했습니다. 검색에는 고유 문단 960개를 모두 사용합니다. 원본 다운로드로 평가 파일 다섯 개의 바이트 해시를 재현했으며, 최종 추론 전에 자료, 설정, 모델 manifest와 소스 및 의존성 파일 19개를 동결했습니다.
2. **질문과 본문 검색에 맞춘 학습.** 공식 학습 자료에서 학습 3,002문항과 내부 검증 206문항을 구성했습니다. 검색 모델의 내부 Recall@5는 최초 96.12%에서 1에포크 100%로 올랐고 2에포크 99.03%로 떨어져 1에포크를 유지했습니다. 재정렬 모델은 동일한 학습 완료 모델에서 일반 음성 예제와 hard negative를 각각 사용해 비교했습니다. 두 경우 모두 기존 100% 내부 지표를 넘지 못해 1에포크 후 중단하고 최초 가중치를 유지했습니다. 기존 모델의 내부 검증 노출 이력이 완전히 확인되지 않고 지표도 포화돼, 음성 예제 방식의 우열을 입증했다고 해석하지 않습니다.
3. **검색과 청크 구성의 전체 서비스 비교.** 최초 모델, 직접 학습한 검색 모델과 여러 청크 길이의 E5를 포함한 개발 구성 여섯 개를 비교했습니다. 최종 검색은 query와 passage 접두어, 마스킹 평균 풀링과 벡터 정규화를 적용한 multilingual E5를 사용합니다. 자연스러운 원문 경계를 보존하는 192토큰 청크와 32토큰 겹침으로 청크 수를 5,889개에서 2,264개로 줄였습니다. 검색 모델, 청크와 입력 길이가 함께 바뀐 결과이므로 개선을 학습 하나의 효과로 설명하지 않습니다. 직접 학습한 모델은 별도 재현 자료로 남겼습니다.
4. **원문과 일치하는 Reader 문맥 및 답변 정책.** 개발 단계에서 Reader 구성 네 개를 비교했습니다. 선택한 구성은 검색 상위 다섯 개를 기준으로 512토큰 내의 원문 문맥을 복원하고 Reader와 재정렬 점수를 함께 사용합니다. 추론에서는 정답 위치를 사용하지 않습니다. 답이 없다는 점수와의 미세한 차이, 원문 인용과 임계값을 검사합니다. 최초 임계값 조합 12개는 모두 공동 기준을 통과하지 못했습니다. 이후 별도 선언한 더 엄격한 조합 아홉 개를 동일 개발 자료에서 비교했으며 기존 품질, 답변 제공률과 같은 GPU의 무응답 기준을 유지했습니다. 여섯 개가 통과했고 선택한 개발 결과는 EM 75.00%, F1 83.01%, 답변 제공률 91.45%, 합성 오답 1/80입니다. 전체 비교 예산이 최초 12개와 후속 9개로 확대된 사실과 실패 기록을 보존했습니다.
5. **환경과 모델 배포의 재현성.** 실행 스크립트가 프로젝트 내부에 고정된 Python과 CPU 의존성을 준비하고, 모델과 인덱스의 목록 및 해시를 검사합니다. 원문은 공식 자료를 내려받아 로컬에서 재구성하며, 서비스는 로컬 safetensors를 사용하고 반복 질문 때 모델을 다시 적재하지 않습니다. Python이 없는 Windows와 Linux에서 자동 준비도 실제 수행했습니다. 최종 모델은 같은 컴퓨터의 분리된 CPU 환경에서 개발 질문 두 개를 각각 두 번 실행해 총 여덟 번의 답변, 판단과 인용이 일치했습니다. 모델 적재는 Windows 14.44초, Linux 11.83초, 관측된 최대 프로세스 메모리는 2.05와 1.64 GiB였습니다. 소규모 환경 검증이며 전체 CPU 성능 평가나 외부 제3자의 독립 검토와 구분합니다. [환경 검증](environment-verification.ko.md)에 자세히 기록했습니다.
6. **검토 가능한 포트폴리오 구성.** 공개 트리는 학습, 선택, 평가와 실행 코드를 중심으로 정리하고 개인 학습 노트북은 로컬 비공개 위치로 옮겼습니다. 영어 기본 문서와 한국어 번역, 최초 모델 변환, 실행 명세와 소스 ZIP, 최종 예측, 출처와 실패 실험을 제공합니다. 기존 STS 검색 모델과 추가 학습 후보는 선택 자료인 [학습 모델 압축 파일](training-artifacts.ko.md)로 공개했으며 비로그인 전체 다운로드와 SHA-256을 확인했습니다. 채택한 E5 실행 구성은 별도 아티팩트를 사용하므로 이 압축 파일에 의존하지 않습니다.

## 최종 개선의 범위와 남은 오류

아래의 재표집은 기록된 질문 그룹을 반복해서 다시 뽑고 두 시스템의 저장된 답으로 성능 차이를 계산하는 bootstrap 방법입니다. 여기서 시드는 무작위 재추출 순서를 고정하는 값이며 모델을 다시 학습했다는 뜻은 아닙니다. 구간은 이러한 그룹 구분을 가정했을 때 관찰한 표본의 변동을 나타냅니다.

대응 비교에서 새로 정답을 맞힌 문항은 82개이고 기존 정답을 놓친 문항은 27개여서 순증가는 55개입니다. 문자 F1은 98문항에서 개선되고 38문항에서 떨어졌습니다. 문단과 중복 질문으로 연결된 102개 그룹을 시드 378로 2,000회 재표집한 설명적 95% 구간은 EM 변화 +6.94–+15.26%p, F1 변화 +5.35–+13.37%p입니다. 기사 의존성, 사전 학습 자료 노출과 개발 과정의 적응적 선택을 반영한 일반적인 통계적 유의성 주장은 아닙니다.

최종 모델에도 답이 있는 질문의 보류 61건과 정확히 일치하지 않은 답변 73건이 남아 있습니다. 정답 구간을 포함한 청크가 상위 다섯 개에 있는데도 보류한 경우가 51건, 잘못 답한 경우가 68건입니다. 이는 추가 점검의 위치를 보여 주며 구성 요소별 인과관계를 확정하지 않습니다. 복원된 문맥이 청크 밖의 정답을 포함할 수도 있고, 원문에 답변 문자열이 있다는 사실만으로 질문의 대상과 관계에 맞는 답이라고 보장할 수도 없습니다.

무응답 처리는 분명한 한계입니다. 가상 개체의 정체를 묻는 유형에서 새로운 오답 네 건이 발생했고, 최초 모델의 가상 관계 오답 한 건은 바로잡혔습니다. 전체 오답은 1/80에서 4/80으로 증가했습니다. 개발 자료에서 맞춘 무응답 조건이 최종 자료에도 그대로 유지되지는 않았습니다. 최종 설정은 개발 단계에서 선택한 기본값으로 보존하고 최초 모델도 별도로 재현할 수 있게 했습니다. 이 결과를 보고 임계값을 다시 조정하지 않았습니다. 합성 자료이므로 실제 사용자의 자연스러운 질문에 대한 오류율로 일반화하지 않습니다.

동결한 최종 모델을 별도 Windows CPU 환경에서도 합성 최종 80문항 전체에 실행했습니다. GPU와 동일한 네 질문에서 잘못 답했고 응답 또는 보류 판단의 불일치는 0건이었습니다. 설정을 유지한 추가 장치 확인이며 답이 있는 501문항 전체의 CPU 성능 측정과는 구분합니다. [합성 자료 CPU 검증](synthetic-final-cpu-audit.ko.md)에 기록했습니다.

## 결과 확인과 재현

분리된 Windows와 Linux 순수 CPU 환경에서 각각 전체 단위 검사 **112개 중 109개 통과, 선택적인 과거 자료 검사 3개 생략**을 확인했습니다. Linux는 소스를 읽기 전용으로 연결하고 네트워크를 차단했습니다. 검사 파일 두 개의 임시 경로만 조정했으며 검증 조건은 유지했습니다. 영향받는 검사 15개도 Windows에서 다시 통과했습니다. 실제 작은 모델의 최적화 실행, 변경된 모델 파일 거부, 자료 분리, 원문 위치, 비교 예산과 환경 격리를 검사합니다. 두 최종 실행 모두 581개 질문 ID의 대응, 동결 해시, 저장된 Reader 결과의 판단 재생과 성능 재계산을 독립적으로 확인했습니다. 수치 감사는 새로운 모델 추론을 수행하지 않습니다.

게시 후 새 소스 폴더와 빈 모델 캐시에서 인증정보 없이 공개 다운로드만 사용해 실제 기본 Windows CPU 준비 과정도 통과했습니다. 준비에는 223.43초가 걸렸고 두 반복 세션의 예시 추론 여섯 번에서 판단 일치와 오프라인 재사용을 확인했습니다. 예시 두 개는 모두 보류됐으므로 답변 정확도와 구분하는 배포 및 실행 검사입니다. 최초 확인한 소스 ZIP과 유지된 핵심 파일 19개는 [공개 다운로드 검증](public-download-verification.ko.md)에 기록했습니다. 계정의 Actions 비활성화로 GitHub 자동 실행은 거절됐으며 완료한 로컬 검사와의 차이는 [CI 상태](ci-status.ko.md)에 남겼습니다.

[수치 비교 JSON](final/final-comparison.json), [최초 지표](final/final-original-metrics.json), [최종 지표](final/final-selected-metrics.json), [개발 검색 비교](development-retrieval.ko.md), [개발 정책 비교](development-calibration.ko.md), [검사 기록](verification-tests.json)과 [실행 안내](../docs/runtime.ko.md)를 제공합니다. 공개 예측은 원문, 질문과 정답을 제외하며, 공개 파일 해시는 로컬의 전체 증거 파일 해시와 구분합니다.

환경과 최종 모델을 준비한 뒤 공식 다운로드에서 평가 자료를 재구성하고 새 결과 폴더에 실행합니다.

```powershell
.venv\Scripts\python.exe scripts\reproduce_data.py --output-dir .local\benchmark-v1
.venv\Scripts\python.exe scripts\evaluate_portable.py --bundle artifacts\runtime --benchmark .local\benchmark-v1 --split final --no-answer reports\no-answer-v1\final.jsonl --freeze configs\selected-freeze.json --device cpu --output .local\reproduced-final
```

Linux에서는 `.venv/bin/python`과 슬래시 경로를 사용합니다. 측정한 GPU 조건을 재현하려면 안내된 CUDA 환경을 준비하고 `--device cuda`로 실행합니다. 연산 장치에 따라 미세한 점수와 판단이 달라질 수 있습니다. 최초 모델은 [문서의 변환과 모델 준비 절차](../docs/runtime.ko.md)를 따른 뒤 `artifacts/original`, `configs/original-freeze.json`과 별도 결과 경로로 비교합니다. 파일 해시는 측정 대상의 동일성을 확인하며 모든 장치의 비트 단위 계산 일치를 보장하지 않습니다.
